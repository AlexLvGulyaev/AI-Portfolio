# E2E-каркас консоли «Источники и синхронизация» (§4.6.3)

## Как запускать

На VPS в нативной среде (playwright + chromium уже установлены):

```bash
cd /opt/ai-automation-portfolio-lab/cases/ai-portfolio
python3 e2e/run_admin_console_e2e.py --only E1 E2
```

- Читает `ADMIN_API_TOKEN` из `.env` (вывод токена в лог запрещён).
- Прогон против production `https://ai.alex-n8n.site/admin`, headless chromium 1920×1080.
- Вывод — только текст PASS/FAIL (скриншоты запрещены, см. CLAUDE.md).

## Что покрывается

| Сценарий | Тип | Гейт владельца |
|---|---|---|
| E1 — навигация, стрип, пагинация, поиск, гидратация трёх панелей | авто, read-only | нет |
| E2 — семантика статусов и корпуса (1:1:1, backfill-регресс, привязка к реестру E2.5) | авто, read-only | нет |
| E3 — полный допуск TAIG (`AlexLvGulyaev/telegram-ai-gateway`) | human-driven: владелец действует в UI, каркас сверяет каждый шаг (DOM ↔ API ↔ БД) | перед каждым мутационным шагом |
| E4 — «Синхронизировать KB» с консоли | human-gated (production-мутация корпуса Chroma) | да |
| E5 — реальный файл в одобренном репо, полный путь владельца | human-driven | да |

Детальный чек-лист E3 и регламент: `task_history/2026-08-29_task-aip-e2e-admission-console.md`.

## Принципы

1. **Human-in-the-loop**: read-only шаги автоматические; шаги, изменяющие production-данные, выполняются только после явного подтверждения владельца в диалоге каркаса (или его физического действия в браузере).
2. **Трёхсторонняя сверка**: утверждения всегда против DOM и API и PostgreSQL — UI не может «врать» локально.
3. **Только текст**: PASS/FAIL-протокол, без скриншотов.
4. Протокол прогонов фиксируется в задаче `2026-08-29_task-aip-e2e-admission-console.md`.
