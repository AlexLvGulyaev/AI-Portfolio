# Глоссарий AI Portfolio

Определения терминов, которыми оперируют документы и проекты этого портфеля.

Для каждого термина даётся общее определение (1–2 предложения) и — принципиальная часть — как термин используется именно в этом портфеле. Это позволяет отвечать и на вопрос «что это вообще», и на вопрос «где в портфеле это применено».

---

## RAG (Retrieval-Augmented Generation)

**Определение.** Подход к построению LLM-приложений: перед ответом модели система находит релевантные фрагменты в своей базе знаний (векторный поиск по проиндексированным документам) и передаёт их в контекст запроса. Ответ генерируется на основе найденных материалов, а не общей памяти модели, — это снижает долю выдумок и позволяет давать ссылки на источники.

**В этом портфеле.** RAG — основа ключевых LLM-проектов: AI Curator, Review Flow и Assistant Flow построены вокруг баз знаний из корпусов документации; сам сайт AI Portfolio работает на RAG-ассистенте, который отвечает по проиндексированным документам портфеля.

## LLM (Large Language Model, большая языковая модель)

**Определение.** Нейросетевая модель, генерирующая и анализирующая текст: отвечает на вопросы, классифицирует, суммаризирует, извлекает данные.

**В этом портфеле.** Проекты используют LLM через API нескольких провайдеров (OpenAI, GigaChat) — с переключаемым активным провайдером и настраиваемыми параметрами.

## Чанк (chunk)

**Определение.** Фрагмент документа фиксированного или смыслового размера, на который разбивается текст перед индексацией в векторной базе. Поиск идёт по чанкам, а не по целым документам.

**В этом портфеле.** Чанки — единицы базы знаний ассистента сайта (3285 чанков по 225 документам на момент описания); каждый ответ ассистента опирается на найденные чанки, а источники раскрываются до документа и репозитория.

## Embedding (эмбеддинг)

**Определение.** Численный вектор, представляющий смысл фрагмента текста: близкие по смыслу фрагменты получают близкие векторы. Сравнение векторов позволяет находить релевантное по смыслу, а не по совпадению слов.

**В этом портфеле.** Эмбеддинги — механика поиска во всех RAG-проектах портфеля: индексация и подбор документов для ответов ассистента идут через векторные представления текста.

## Векторная база данных

**Определение.** Хранилище эмбеддингов с поиском по близости векторов. Обычно поддерживает метаданные, фильтрацию и удаление по документу.

**В этом портфеле.** Платформа поддерживает несколько бэкендов — ChromaDB и Weaviate (активный), — переключаемых из админ-консоли без остановки сервиса; выбор бэкенда — эксплуатационное решение, видимая в консоли «Retrieval».

## Релевантность и порог поиска

**Определение.** В векторном поиске каждая пара «запрос — чанк» получает численную оценку близости; конвейер отбирает top-k чанков с учётом порога расстояния, чтобы в контекст ответа попадали только действительно связанные с вопросом фрагменты.

**В этом портфеле.** Параметры поиска (top-k, порог расстояния, размер чанков) вынесены в консоль «Retrieval» админ-консоли и настраиваются без кода; их влияние на корректность проверялось в eval-кампаниях (см. `docs/AI_EVAL_REPORT.md`).

## База знаний (KB, Knowledge Base)

**Определение.** Индексированный корпус документов, по которому ассистент ищет факты для ответов. Качество и состав KB напрямую определяют качество ответов.

**В этом портфеле.** KB ассистента сайта собирается синхронизацией с GitHub-репозиториями проектов портфеля: только документы, прошедшие допуск по качеству, попадают в индекс. Управление составом — в админ-консоли (консоли «Допуск», «Документы», «Retrieval»).

## Admission gate (допуск источников)

**Определение.** Механизм проверки качества документации перед подключением источника к базе знаний: источник либо допущен целиком, либо допускается по включающим/исключающим шаблонам.

**В этом портфеле.** Реализован в админ-консоли AI Portfolio (fail-closed): источник нельзя проиндексировать без пройденного допуска; каждое решение о допуске фиксируется в журнале аудита.

## Grounding (привязка ответов к источникам)

**Определение.** Принцип построения ответов ассистента: факты берутся только из подтверждённых источников (реестра и документов KB); при отсутствии сведений ассистент честно сообщает об этом, не достраивая ответ из памяти модели.

**В этом портфеле.** Встроено в системный промпт ассистента: «если информации нет — честно скажи, не достраивай из догадок». Этим объясняются и корректные ответы, и честные отказы: ассистент не галлюцинирует несуществующие проекты.

## n8n

**Определение.** Платформа автоматизации рабочих процессов (low-code workflow automation): визуально строит конвейеры интеграций между сервисами, API и AI-моделями.

**В этом портфеле.** Используется в проекте Lead Qualification: n8n-конвейер принимает входящие заявки, AI-классификация определяет тип и приоритет лида, результат передаётся в CRM.

## AI-классификация / AI-роутинг

**Определение.** Применение LLM для сортировки входящих сущностей (заявок, сообщений, обращений) по смыслу: определение типа, приоритета, направления обработки без ручных правил.

**В этом портфеле.** Central-приём в Lead Qualification (классификация входящих лидов с передачей в CRM); в других проектах — маршрутизация запросов ассистента (RAG/текст/голос).

## Telegram-бот

**Определение.** Программа-помощник в мессенджере Telegram, ведущая диалог с пользователем через Bot API: приём сообщений, кнопки, сценарии состояний.

**В этом портфеле.** Самое массовое направление: Telegram Intake Bot (приём обращений), Telegram Onboarding Bot (онбординг сотрудников, FSM-сценарии), HR Assistant (подбор, TTS), Meeting Audit Bot (аудит встреч).

## STT / TTS (speech-to-text / text-to-speech)

**Определение.** STT — распознавание речи в текст; TTS — синтез речи из текста. Вместе превращают текстовые AI-системы в голосовые.

**В этом портфеле.** STT — в Meeting Audit Bot (транскрибация и аудит встреч); TTS — в HR Assistant (голосовые ответы ассистента).

## Fine-tuning / LoRA

**Определение.** Дообучение готовой LLM на своих данных. LoRA — техника, при которой обучается маленькая «надстройка» над моделью вместо всей модели: дешевле, быстрее, достаточно для узких задач.

**В этом портфеле.** HR Assistant — LoRA Fine-Tuning: дообучение Qwen под задачу сопоставления вакансий и кандидатов — отдельный проект, подтверждающий ML-компетенцию за пределами API-интеграций.

## Multi-provider LLM

**Определение.** Архитектура, в которой приложение умеет работать с несколькими провайдерами LLM (например, OpenAI и GigaChat), переключаясь между ними без изменения логики продукта.

**В этом портфеле.** Реализовано в нескольких проектах и в самой платформе: провайдеры, параметры и fallback настраиваются из админ-консоли; переключение провайдера фиксируется в журнале.

## Eval / eval-кампания

**Определение.** Системная проверка качества AI-ассистента на контрольном наборе вопросов с фиксацией корректности, скорости и регрессий между итерациями.

**В этом портфеле.** Каждая крупная версия ассистента сопровождается прогоном eval-набора; итоги публичны: см. `docs/AI_EVAL_REPORT.md` (полный прогон 24/24 сценариев, p95 времени ответа 2599 мс на момент отчёта).

## Reverse proxy (обратный прокси)

**Определение.** Сервер-посредник, который принимает запросы пользователей и передаёт их внутренним сервисам приложения: распределяет нагрузку, терминирует HTTPS, раздаёт статику.

**В этом портфеле.** Инфраструктура платформы AI Portfolio построена на двух уровнях: nginx (статический frontend + reverse proxy к backend) и Traefik (внешний edge-прокси с автоматическим SSL через Let's Encrypt).

## nginx

**Определение.** Высокопроизводительный веб-сервер, обычно используемый для раздачи статики и проксирования запросов к backend-сервисам.

**В этом портфеле.** Обслуживает пользовательские страницы платформы (HTML/CSS/JS) и проксирует запросы к FastAPI-backend; настройка — часть docker-конфигурации репозитория.

## Traefik

**Определение.** Современный reverse proxy и балансировщик, автоматически обнаруживающий контейнеры Docker и выпускающий SSL-сертификаты.

**В этом портфеле.** Внешний вход production-развертывания платформы: HTTPS-терминация и автоматические сертификаты Let's Encrypt для ai.alex-n8n.site.

## Docker / Docker Compose

**Определение.** Docker упаковывает приложение со всеми зависимостями в контейнер — изолированную и воспроизводимую единицу запуска; Docker Compose описывает запуск нескольких связанных контейнеров (приложение, база, векторное хранилище) одной командой.

**В этом портфеле.** Основной способ развертывания платформы и её проектов: compose-стек AI Portfolio поднимает backend, PostgreSQL, векторное хранилище и nginx; README содержит быстрый старт production-подобного развертывания.

## Docker E2E

**Определение.** End-to-end тестирование — проверка сквозных пользовательских сценариев от входа к результату — выполняемое в Docker-окружении, воспроизводимом на любой машине.

**В этом портфеле.** AI Data Assistant: сквозные тесты поднимают проект целиком в Docker и прогоняют пользовательские сценарии (запрос — график — отчёт).

## LangFlow

**Определение.** Визуальный конструктор LLM-приложений: потоки промптов, инструментов и моделей собираются из блоков в интерфейсе, без кода.

**В этом портфеле.** Один из backend-вариантов Prompt Review: проверка промптов доступна на LangFlow-бэкенде через Web UI, Telegram-бота или REST API.

## LangChain

**Определение.** Кодовый фреймворк для сборки LLM-приложений: единые абстракции для моделей, шаблонов промптов, памяти и цепочек вызовов.

**В этом портфеле.** Используется на двух уровнях: AI Curator строит на LangChain свой RAG-конвейер (эмбеддинги, обработка документов, адаптер LLM); в Prompt Review это один из backend-вариантов наряду с LangFlow — выбор бэкенда не меняет продукт (Web UI, Telegram-бот и REST API работают поверх обоих).

## RBAC (role-based access control, ролевое разграничение доступа)

**Определение.** Модель управления доступом, в которой права определяются ролью пользователя (оператор, администратор, гость), а не выдаются персонально каждому.

**В этом портфеле.** Review Auto Responder (demo-RBAC операторской панели), Telegram Onboarding Bot (RBAC на смену глобальной темы), Review Flow (staff-контур) и админ-консоль самой платформы.

## FSM (finite-state machine, конечный автомат)

**Определение.** Подход к диалоговым ботам: разговор разбит на состояния со строгими переходами — надёжно для форм и онбординга, где нельзя потерять введённые данные.

**В этом портфеле.** Telegram Onboarding Bot — FSM-сценарии онбординга новых сотрудников: последовательные шаги с подтверждениями и устойчивостью к сбоям.
