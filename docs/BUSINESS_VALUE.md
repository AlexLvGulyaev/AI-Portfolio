# 💼 BUSINESS_VALUE — AI Portfolio

**Основной читатель:** заказчик AI-автоматизации — тот, кто решает, кому отдать задачу.
**Назначение:** показать, какая проблема закрывается платформой и услугами, что получает заказчик и как строится работа. Технические детали — в [`docs/ARCHITECTURE.md`](ARCHITECTURE.md); живая демонстрация — на https://ai.alex-n8n.site.

---

## ⚠️ 1. Проблема

### 1.1. Для заказчика AI-автоматизации

Найти и проверить исполнителя AI-решений трудно:

- **Обещания не проверяются до контракта.** Портфолио из скриншотов и презентаций не показывает, как решение реально ведёт себя на вопросах клиента.
- **«Кейсы» без доступа** — картинки без живого продукта, кода и документации.
- **Компетенции заявлены, но не измерены.** «Делаем AI» — не ответ на вопрос «какого качества будет ассистент по моей базе знаний?».
- **Ручные процессы съедают время команды:** однотипные ответы клиентам, разбор входящих заявок и резюме, транскрибация и аудит встреч, поддержка документации.

### 1.2. Для владельца базы знаний

Документация и материалы накоплены, но к ним нет доступа «по-человечески»: поиск по файлам не отвечает на вопросы, а универсальный чат-бот отвечает по памяти модели — в том числе выдумывает.

---

## 💡 2. Решение

**AI Portfolio — витрина исполнителя, где каждый элемент доказателен:**

1. **13 реализованных кейсов** с лендингами по единому стандарту (результат, проблема/решение, метрики, сценарии) и публичными GitHub-репозиториями.
2. **Живой AI-ассистент на самой витрине** — работающий RAG-ассистент по документации этих репозиториев: тот класс решения, которое заказчик получает для своей базы знаний.
3. **Измеримое качество** — ассистент прошёл контрольные eval-прогоны: корректность 94,6%, p95-задержка < 5 секунд ([`docs/AI_EVAL_REPORT.md`](AI_EVAL_REPORT.md)).
4. **Прозрачная инженерия** — архитектура, промпт-архитектура, eval-методика и руководство развёртывания открыты в документации.

Услуги исполнителя: автоматизация процессов под ключ — проектирование, реализация, production-развёртывание на хостинге заказчика, сопровождение. Состав задач — на странице [Услуги](https://ai.alex-n8n.site/services.html).

## 📊 3. Как создаётся ценность

### 3.1. 🤝 Для заказчика услуг

- **Проверка до контракта:** задайте вопрос ассистенту — качество ответов, привязка к источникам и честные отказы видны до первого разговора о цене.
- **Сокращённый путь к релевантному кейсу:** вместо чтения 13 репозиториев — вопрос ассистенту; он найдёт кейс, который закрывает вашу задачу.
- **Предсказуемое качество:** тот же контур (управляемый допуск материалов, grounding, eval) переносится на базу знаний заказчика.

### 3.2. 🗄️ Для владельца базы знаний

- **Ответы с указанием источников** — каждый содержательный ответ привязан к документам, из которых он собран.
- **Контроль состава знаний:** каждый документ проходит допуск (draft-правила → превью с фиксацией версии репозитория → утверждение → синхронизация) — в ответы попадают только одобренные и актуальные материалы.
- **Честный отказ:** если сведений нет, ассистент говорит об этом прямо.

### 3.3. 🛡️ Для администратора решения

- Полный операционный контур: Admin Console с контролем контента и допуска, retrieval- и AI-настройками (включая управляемый системный промпт с историей версий), логами, диалогами, аудитом и пресейл-воронкой.
- Multi-provider LLM с фоллбэком: недоступность одного провайдера не останавливает ответы.

## 🧭 4. Наш метод

Как устроен каждый элемент витрины — от кейса до ассистента:

1. **Доказательство работой.** Каждый кейс — реализованный проект с лендингом по единому стандарту (результат, проблема/решение, метрики, сценарии) и публичным GitHub-репозиторием: продукт можно открыть, прочитать и повторить.
2. **Живой ассистент вместо витрины картинок.** Ассистент отвечает по документации тех самых репозиториев — это работающий образец RAG-решения, которое заказчик получает для своей базы знаний.
3. **Качество измерено.** Ассистент прошёл контрольные eval-прогоны: корректность 94,6%, p95-задержка < 5 секунд — методика и итоги открыты ([`docs/AI_EVAL_REPORT.md`](AI_EVAL_REPORT.md)).
4. **Каждый документ допускается и утверждается.** Материалы попадают в базу знаний через управляемый допуск: draft-правила → immutable-превью с фиксацией версии репозитория → утверждение владельцем → синхронизация. В ответы идут только одобренные и актуальные документы.
5. **Честность как правило.** Когда сведений в реестре и документах нет, ассистент отвечает об этом прямо — ответы строятся на фактах источников.
6. **Прозрачная инженерия.** Архитектура, промпт-контур, eval-методика и руководство воспроизводимого развёртывания открыты в документации проекта.

## 🏢 5. Целевые заказчики

- **Малый бизнес с ручными процессами** — боты и n8n-контуры: приём заявок, квалификация лидов, автоответы, уведомления.
- **Компании с накопленной базой знаний** — ассистенты по документации, FAQ, внутренней вики.
- **Образовательные платформы** — ассистенты поверх LMS и учебных материалов.
- **HR-команды** — обработка резюме, matching кандидатов и вакансий.

---

## ⚠️ 6. Риски и ограничения (честно)

- **Конверсия сайта пока не доказана сделками:** витрина запущена, baseline конверсии посетителей в обращения собирается; коммерческих заказов на текущий момент не зафиксировано.
- **Качество источников неоднородно:** документация не всех портфельных проектов доведена до единого стандарта — это известное ограничение, контролируется допуском материалов в базу знаний (в индекс попадают только одобренные документы).
- **Зависимость от внешних API:** LLM-провайдеры и GitHub (синхронизация знаний) — внешние сервисы; для LLM настроен фоллбэк, для ретривера резервный канал пока не реализован.
