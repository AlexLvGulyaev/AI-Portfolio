# 🎛️ ADMIN_GUIDE — AI Portfolio

**Основной читатель:** администратор/оператор развёртывания — тот, кто ведёт базу знаний, настройки и наблюдаемость.
**Назначение:** повседневные операции Admin Console: допуск источников KB, управление карточками, retrieval- и AI-настройки, мониторинг. Техническое устройство консоли — в [`docs/ADMIN_CONSOLE_ARCHITECTURE.md`](ADMIN_CONSOLE_ARCHITECTURE.md).

---

## 🔐 1. Вход и доступ

| Параметр | Значение |
|----------|----------|
| URL | https://af-admin.alex-n8n.site |
| Аутентификация | bearer-токен `ADMIN_API_TOKEN` (задаётся в `.env`, меняется вместе с перезапуском backend) |
| Время в интерфейсе | местная зона зрителя (сервер отдаёт UTC, браузер отображает локально) |
| Аудит | вход в админку и все мутации консолей пишутся в журнал аудита (раздел «Аудит») |

Меню консоли — пять групп: **Система**, **База знаний**, **Аналитика**, **Наблюдаемость**, **Справка**.

## 🧭 2. Типовые операции

### 2.1. 📥 Добавить кейс в базу знаний (полный цикл)

1. **База знаний → Карточки проектов** — создайте карточку проекта (slug, название, категория, описание, порядок).
2. **База знаний → Источники и синхронизация → «Добавить источник»** — добавьте GitHub-репозиторий кейса (`owner/repo`); ветка подставляется автоматически по умолчанию.
3. Задайте **draft-правила допуска** (include/exclude-паттерны по путям). По умолчанию правила пустые — превью включает 0 файлов, пока правила не заданы.
4. Снимите **Preview состава** — превью фиксировано по commit SHA репозитория.
5. Проверьте список кандидатов и **утвердите** — draft-правила становятся эффективными.
6. Запустите **синхронизацию** — документы уходят в векторный индекс.
7. Проверьте результат: **База знаний → Документы** (документы и чанки в активном бэкенде), затем задайте ассистенту контрольный вопрос на сайте.

### 2.2. 🔄 Обновить материалы существующего источника

После коммитов в репозиторий кейса источник переходит в состояние «Есть изменения»:

1. Снимите новый Preview (состав пересчитается по свежему commit SHA).
2. Проверьте различия состава, утвердите, запустите синхронизацию.

Состав источника редактируется в блоке «Состав источника для KB»:

- **«Обновить состав»** — пересборка списков с GitHub по текущим правилам; новые файлы репозитория попадают в «исключено» (черновик);
- **«Сохранить»** — утверждение изменённого состава (доступна, когда состав действительно изменился; иначе кнопка неактивна с подсказкой «Изменений состава нет»).

Черновик правил, идентичный эффективным, изменением состава не считается — источник не «зависает» в статусе «Есть изменения» (фикс 03.09.2026).

Правило: эффективные правила меняются только через утверждение превью — прямое редактирование источника API отклоняет (`409 use_admission_actions`).

### 2.3. 📝 Обновить системный промпт ассистента

1. **Система → AI-настройки** — панель «Системный промпт»: активная версия, редактор, история.
2. Отредактируйте текст (тело обязано содержать все плейсхолдеры — сохранение без них отклоняется с 422).
3. Сохраните новую версию → «Сделать активной». Смена активного промпта автоматически инвалидирует кеш ответов.
4. Откат в любую историческую версию — кнопкой «Сделать активной» в списке версий; возврат к вшитому fallback — «Сброс к вшитому».
5. Экспорт и архитектура промпта — [`docs/PROMPT_ARCHITECTURE.md`](PROMPT_ARCHITECTURE.md).

### 2.4. 🔍 Настроить Retrieval

**Система → Retrieval** — рабочие параметры поиска: пороги и лимиты ретривера, runtime-таймауты и лимиты генерации, retrieval-кеш (тумблер и очистка работают без рестарта; после синхронизации знаний кеш инвалидируется автоматически). Часть индексирующих параметров применяется только при полном ресинке — консоль помечает такие поля честным флагом.

### 2.5. 🩺 Проверить здоровье системы

1. **Система → Обзор** — панель состояния: бэкенды (PostgreSQL, векторный стор, LLM-провайдеры), объём KB, Last Sync.
2. **Наблюдаемость → Логи** — execution-сессии чата: шаги пайплайна, latency, ошибки.
3. **Наблюдаемость → Аудит** — входы в админку, визиты сайта, переключения провайдеров, админ-действия.

## 🚦 4. Статусы источника допуска

Значок статуса виден в списке источников и в опциях фильтра; расшифровка — в «Справка → Обозначения»:

| Значок | Статус | Смысл |
|--------|--------|-------|
| 👀 | Нужен preview | Правила изменены, превью следует снять |
| 📷 | Preview готов | Превью снято, ожидает утверждения |
| ✅ | Одобрен | Правила утверждены, источник допущен |
| 🔄 | Есть изменения | В репозитории источника новые коммиты — снимите свежее превью |
| 🚫 | Заблокирован | Источник исключён из синхронизации (с указанием причины) |
| ❌ | Ошибка | Ошибка на предыдущей операции — смотрите детали в карточке источника |

Защита одобрения от устаревания: если после снятия превью изменились правила или commit репозитория, утверждение отклоняется (`409` с машиночитаемой причиной) — снимите превью заново.

## ⚠️ 5. Правила и ограничения

- **Реестр карточек — SOT состава витрины:** состав индекса знаний строится вокруг карточек; мета-карточка платформы (`ai-portfolio`) защищена — её отображение меняется только миграцией, удаление отклоняется (`409 meta_card_protected`).
- **Источник знания — только GitHub-репозиторий,** привязанный к карточке проекта; загрузка файлов напрямую отсутствует by design.
- **Удаление** источника, карточки и черновиков — осознанные операции с подтверждением; аудируются.
- Переиндексация — явная операция синхронизации: администратор контролирует состав и момент каждого прогона.

## 🆘 6. Типовые ситуации

| Симптом | Причина и действие |
|---------|--------------------|
| Источник падает с ошибкой при создании превью | Проверьте публичность репозитория и ветку; корректная ветка — дефолтная ветка репозитория (подставляется автоматически при создании) |
| Синхронизация сообщила частичные ошибки батча | Операция завершена отказом; исправьте состав правил (исключите проблемные файлы) и повторите синхронизацию |
| Ассистент отвечает «информации нет» на знакомый вопрос | Проверьте статус источника (Одобрен), свежесть синхронизации и состав правил в «Источники и синхронизация» |
| Ответы ассистента устарели после правки промпта | Убедитесь, что новая версия сделана активной; кеш ответов инвалидируется автоматически |
| Пропадает доступ к консоли | Проверьте `ADMIN_API_TOKEN` в `.env` и перезапуск backend после его смены |
