# 📡 API_CONTRACT — публичный API AI Portfolio

**Основной читатель:** интегратор/инженер — кто вызывает API платформы напрямую или встраивает компоненты в свою систему.
**Назначение:** контракт публичных HTTP-эндпойнтов: запрос, ответ, коды ошибок, ограничения. Админ-контур (`/api/admin/*`) — bearer-токен, описан в [`docs/ADMIN_CONSOLE_ARCHITECTURE.md`](ADMIN_CONSOLE_ARCHITECTURE.md) и не является публичным контрактом.

> 📌 **SOT:** раздел описывает фактическое поведение production-развёртывания `https://ai.alex-n8n.site` (nginx → FastAPI backend). Источник контракта — код `backend/app/api/`; при расхождении исправляется документация.

## 🌐 1. Общие положения

| Параметр | Значение |
|----------|----------|
| База | `https://ai.alex-n8n.site` (HTTPS, TLS завершается на nginx) |
| Формат | JSON в теле запроса и ответа; UTF-8 |
| Аутентификация публичных эндпойнтов | нет; публичные эндпойнты — только чтение/анонимный трекинг/чат |
| Идентификация клиента | анонимный `visitor_id` (стабильный id посетителя, генерируется фронтом); IP берётся из `X-Forwarded-For`/`X-Real-IP` с учётом reverse-proxy |
| CORS | задаётся переменной `CORS_ORIGINS` (обязательна, см. [`docs/DEPLOYMENT_GUIDE.md`](DEPLOYMENT_GUIDE.md)) |
| Health | `GET /health` — проверка живости |

**Ограничение частоты:** публичные API-эндпойнты ограничиваются nginx rate limit'ом — **10 запросов/минуту на IP клиента** с burst-окном 20 запросов (гасит веер запросов при загрузке страницы); превышение — `429 Too Many Requests`. Лимит применён к `/chat`, `/project-cards`, `/track-visit`, `/track-event`, `/document-fragment`, `/case-match`; `/health` и админ-контур не ограничиваются. IP клиента восстанавливается из `X-Forwarded-For` (edge-прокси Traefik — единственное доверенное звено). Настройка `RATE_LIMIT_REQUESTS_PER_MINUTE` backend-конфигурации зарезервирована — enforcement на уровне nginx.

## 💬 2. `POST /chat` — вопрос ассистенту

Единственная публичная точка входа диалогового контура.

### Запрос

| Поле | Тип | Обязательное | Описание |
|------|-----|--------------|----------|
| `message` | string | да | Вопрос пользователя |
| `session_id` | UUID | нет | Идентификатор сессии диалога. Не передан — создаётся новая сессия. **Сервер валидирует переданный id:** несуществующая сессия заменяется новой (клиентский id не пробрасывается вслепую — для диалоговой группы берите `session_id` из первого ответа) |
| `visitor_id` | string | нет | Стабильный анонимный id посетителя (для связности аналитики) |
| `page_slug` | string | нет | Slug кейс-страницы, с которой задан вопрос. Принимается только при совпадении с реестром карточек; в промпт попадает доверенное название проекта из реестра (роутинг «этот кейс»), сырой текст не пробрасывается |

```json
{ "message": "Какие кейсы про обработку резюме?", "visitor_id": "v-1a2b3c" }
```

### Ответ `200`

| Поле | Тип | Описание |
|------|-----|----------|
| `answer` | string | Текст ответа ассистента |
| `session_id` | UUID | Сессия диалога (передавайте в следующих вопросах для продолжения диалога) |
| `sources` | string[] | Читаемые лейблы источников ответа (`репозиторий · документ`) |
| `sources_detail` | object[] \| null | Machine-readable provenance: `[{repo, path, chunk_index, score, excerpt, label, html_url}, …]` — основа панели документа |
| `provider` | string | Активный LLM-провайдер ответа (`openai` / `gigachat`) |
| `model` | string | Идентификатор модели |
| `from_cache` | bool | Ответ из кеша (детерминированные ответы реестра; grounded LLM-ответы по признаку cache-eligible — первый вопрос сессии, rag_used, без канонического отказа и fallback; дословные повторы вопроса в той же сессии — чтение кеша по нормализованному совпадению) |
| `rag_used` | bool | Использовался ли retrieval по базе знаний |
| `response_time_ms` | int | Полная латентность обработки |
| `user_id`, `visitor_id` | UUID \| null | Идентификаторы учёта |

```json
{
  "answer": "Резюме обрабатывают HR Assistant и HRA-LoRA…",
  "session_id": "5f0c…",
  "sources": ["AlexLvGulyaev/HR-Assistant · README.md"],
  "sources_detail": [{ "repo": "AlexLvGulyaev/HR-Assistant", "path": "README.md", "chunk_index": 4, "score": 0.63, "excerpt": "…", "label": "HR-Assistant · README", "html_url": "https://github.com/…/blob/main/README.md" }],
  "provider": "openai", "model": "…", "from_cache": false, "rag_used": true,
  "response_time_ms": 2366, "user_id": null, "visitor_id": null
}
```

### Коды ошибок

| Код | Когда |
|-----|-------|
| 422 | Некорректное тело запроса (валидация Pydantic) |
| 500 | Ошибка обработки контура (в `detail` — обобщённое сообщение) |

### Поведение, важное для клиента

- Факты ответа — только из официального реестра проектов и допущенных документов KB; при отсутствии сведений ассистент отвечает честным отказом (см. [`docs/FAQ.md`](FAQ.md)).
- Диалоговая память: `session_id` из ответа продолжает диалог; сведения о пользователе ассистент берёт из истории сессии.
- Latency на cache-miss: p50 ≈ 2,4 с, p95 < 5 с ([`docs/AI_EVAL_REPORT.md`](AI_EVAL_REPORT.md)).

## 🗂️ 3. `GET /project-cards` — состав витрины

Публичное чтение реестра карточек (SOT состава портфеля — PostgreSQL `project_cards`).

### Ответ `200`

```json
{ "items": [
  { "id": "uuid", "slug": "ai-curator", "title": "AI Curator",
    "short_description": "…", "category": "Образование / RAG",
    "tags": ["FastAPI", "RAG"], "display_order": 1,
    "show_on_homepage": 1, "external_url": "https://…",
    "icon_path": "M13 10V3L4 14h7v7l9-11h-7z" } ] }
```

| Поле | Описание |
|------|----------|
| `items` | Только видимые карточки (`is_visible`), упорядочены по `display_order`; скрытые и мета-карточка платформы не возвращаются |
| `icon_path` | SVG-путь значка карточки (презентационное поле backend'а для vanilla-фронта) |
| `show_on_homepage` | Флаг featured-секции главной (deprecation: состав витрины определяется `is_visible` + `display_order`) |

## 📊 4. Пресейл-трекинг

Анонимные события пути посетителя; данные обслуживают консоль «Аналитика → Пресейл».

### `POST /track-visit` — визит страницы

Запрос: `{ "visitor_id": "v-…", "path": "/cases/hr-assistant.html", "referrer": "…", "user_agent": "…" }` (все поля опциональны).
Ответ: `{ "visitor_id": "v-…" }`.

### `POST /track-event` — шаг воронки

| Поле | Тип | Описание |
|------|-----|----------|
| `event_type` | enum | `case_view` · `inquiry` · `chat_feedback` (оценка ответа ассистента 👍/👎; шагом воронки не является) |
| `visitor_id` | string | Анонимный id посетителя |
| `path` | string | Текущий путь страницы |
| `metadata` | object | Контекст события; **белый список**: только скалярные значения из разрешённых ключей (card/channel-контекст), остальное отбрасывается |

Ответ: `{ "event_type": "case_view", "visitor_id": "v-…" }`.

## 🧲 5. `POST /case-match` — подбор кейсов под задачу

Morphic-подбор (проба): по описанию задачи зрителя возвращает до 3 релевантных кейсов с объяснением применимости. Grounded: retrieval по документам KB + реестр видимых карточек; объяснение генерируется по документам — без обещаний статусов, сроков и цен.

### Запрос

| Поле | Тип | Ограничение |
|------|-----|-------------|
| `task` | string | 5–500 символов |

```json
{ "task": "нужен бот приёма заявок в Telegram с выгрузкой в таблицу" }
```

### Ответ `200`

```json
{ "items": [
  { "slug": "telegram-intake-bot", "title": "Telegram Intake Bot",
    "why": "Приём заявок в Telegram с валидацией и маршрутизацией — прямое закрытие задачи." } ],
  "provider": "openai", "model": "…" }
```

Если прямого соответствия задаче нет — возвращаются 1–2 ближайших по смыслу кейса с честным «why» («прямого кейса про X нет, ближайший…»). Пустой подбор не ошибка.

### Коды ошибок

| Код | Когда |
|-----|-------|
| 422 | `task` короче 5 или длиннее 500 символов |
| 503 | Недоступность LLM-провайдера для объяснения применимости |

## 📄 6. `GET /document-fragment` — фрагмент документа с подсветкой

Фрагмент документа вокруг цитированного чанка — основа панели документа ассистента. Полный документ берётся с `raw.githubusercontent.com` (кеш 600 с / до 128 документов); **ветка — только из реестра допуска KB** (fail-closed: репозиторий не в реестре — отказ).

### Параметры запроса (query string)

| Параметр | Ограничение | Описание |
|----------|-------------|----------|
| `repo` | 3–200 симв. | `owner/repo` — должен быть зарегистрированным источником KB |
| `path` | 1–400 симв. | Путь документа в репозитории |
| `excerpt` | 5–2000 симв. | Текст цитированного чанка (из `sources_detail`) |
| `context_chars` | 500–8000, по умолчанию 3500 | Размер окна фрагмента |

### Ответ `200`

| Поле | Описание |
|------|----------|
| `fragment` | Plain-текст фрагмента с PUA-маркерами U+E000/U+E001 вокруг чанка (фронт рендерит их как подсветку) |
| `located` | Найден ли чанк в текущем виде файла; `false` — документ правили после индексации, показан сам чанк (честный фолбэк) |
| `plain_text` | Всегда `true`: документ хранится в KB как plain-текст (markdown-разметка снята при синхронизации) |
| `total_chars` | Размер plain-представления документа |
| `label` / `html_url` / `repo` / `path` / `branch` | Читаемый лейбл, ссылка на GitHub blob и параметры документа |

### Коды ошибок

| Код | `detail` |
|-----|----------|
| 404 | `repo_not_allowed` — репозиторий отсутствует в реестре допуска |
| 404 | `document_not_found:<http-код>` — файл недоступен в репозитории |
| 422 | Нарушены ограничения параметров |
