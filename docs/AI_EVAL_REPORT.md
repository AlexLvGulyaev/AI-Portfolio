# AI Eval Report — приёмочное тестирование AI-ассистента

> **Статус:** приёмка пройдена, результат утверждён владельцем проекта (28.08.2026).
> **Production:** `https://ai.alex-n8n.site` (FastAPI + PostgreSQL + ChromaDB, KB `ai_portfolio_knowledge_v2`).

---

## 1. Цель и объём

Документ фиксирует итоги приёмочного тестирования AI-ассистента портфолио: корректность ответов, latency, устойчивость к формулировкам и границы поведения. Диагностическая кампания выполнялась на production-инстансе через публичный HTTP API `POST /chat`, без вмешательства в работу обычных пользователей.

Полный диагностический набор (174 теста, трассировки, production-снимки) хранится приватно и не публикуется. В публичный репозиторий вынесен только обезличенный [regression set](../backend/tests/ai_portfolio_eval_set.json) (§6).

## 2. Методика

Тесты разбиты на классы по типу проверяемого поведения:

| Класс | Что проверяет |
|-------|---------------|
| A | Детерминированные ответы реестра: состав витрины (13 проектов), счётчики |
| B | Идентификация проекта по имени и алиасу; различение HRA / LoRA-версии HR-ассистента |
| C | Факты о проектах: назначение, пользователь, каналы, CRM, статус (по документам KB) |
| D | Мульти-проектные ответы: полнота перечисления, сравнение проектов |
| E | Повторяемость: одинаковый вопрос — консистентный ответ |
| F | Диалог: разрешение местоимений («он», «этот проект») без дрейфа фактов |
| H | Честный отказ: несуществующий проект, скрытая карточка, отсутствующий факт |
| M | Устойчивость к формулировкам: опечатки, регистр, краткая форма |

Особенности оценки:

- Проверки выполнялись по структурированным критериям (наличие ожидаемых фактов, полнота перечисления, маркеры отказа), без «суждения модели о модели».
- Ответы класса C сверялись с допущенными документами KB: факт засчитывался только если он присутствует в документах соответствующего проекта.
- Корректность и latency измерялись на production cache-miss (кеш реальных ответов ассистента), многократно — для отделения систематических дефектов от стохастических колебаний генерации.
- Дефекты, найденные кампанией, исправлялись итеративно; финальные цифры — по последнему прогону на финальном коде.

## 4. Что было исправлено в ходе подготовки

Ключевые дефекты, выявленные кампанией и устранённые до приёмки:

1. **Provenance источников** — пользователю показывались имена файлов без репозитория; исправлено на путь «репозиторий/документ».
2. **Изоляция кеша** — кеш-ключ не учитывал версию KB и историю; устранена кросс-сессионная контаминация. Принята политика: детерминированные ответы реестра кешируются, LLM-ответы не кешируются (см. §5).
3. **Дрейф памяти диалога** — история диалога больше не является источником фактов (только для разрешения ссылок); состав портфеля определяется детерминированным реестром из БД, включаемым в промпт.
4. **Полнота мульти-проектных ответов** — правило «включи все подтверждённые проекты, не добавляй неподтверждённые» с компактным форматом перечисления.

## 5. Известные ограничения (принятые)

- Класс C стохастически колеблется между прогонами (~88–96% на один и тот же набор при одинаковой общей оценке) — принято как достигнутый уровень; повторные полные прогоны выполняются только по согласованию с владельцем.
- Запас по latency до лимита 5 секунд минимален (p95 4956 мс); единичные выбросы >5 с составляют менее 3% запросов.
- LLM-ответы временно не кешируются — осознанный компромисс после устранения контаминации кеша; кеширование вернётся с появлением структурного признака кешируемости.
- Retrieval зависит от внешнего провайдера эмбеддингов; резервный канал поиска не реализован (резервный LLM-провайдер генерации настроен).

## 6. Regression set

Публичный контрольный набор: [`backend/tests/ai_portfolio_eval_set.json`](../backend/tests/ai_portfolio_eval_set.json) — 24 вопроса, покрывающих классы A/B/C/D/E/F/H/M.

**Что в наборе:** собственные контрольные вопросы и ожидания, основанные на публичной информации витрины (реестр проектов, публичная документация кейсов).

**Чего в наборе нет:** production-данных (UUID сессий, диалогов посетителей), трассировок, adversarial-кейсов (инъекции через документы, попытки раскрытия системного промпта) — они хранятся приватно.

### Запуск

```python
#!/usr/bin/env python3
"""Прогон публичного regression set на production."""
import json, uuid, requests

BASE = "https://ai.alex-n8n.site"
SET = json.load(open("backend/tests/ai_portfolio_eval_set.json", encoding="utf-8"))
MARKERS = SET["refusal_markers"]

def check(answer: str, c: dict) -> list[str]:
    low = answer.lower()
    errs = []
    if len(answer) < c.get("min_chars", 0):
        errs.append(f"too short ({len(answer)} < {c['min_chars']})")
    for s in c.get("mentions_all", []):
        if s.lower() not in low:
            errs.append(f"missing: {s}")
    any_min = c.get("mentions_any_min")
    if any_min:
        hits = sum(1 for s in c["mentions_any"] if s.lower() in low)
        if hits < any_min:
            errs.append(f"mentions {hits}/{any_min} from mentions_any")
    for s in c.get("not_mentions", []):
        if s.lower() in low:
            errs.append(f"must not mention: {s}")
    if c.get("refusal") and not any(m in low for m in MARKERS):
        errs.append("expected refusal marker")
    return errs

groups: dict[str, str] = {}
failed = 0
for t in SET["tests"]:
    session = groups.setdefault(t.get("session_group", ""), str(uuid.uuid4()))
    r = requests.post(f"{BASE}/chat", json={
        "message": t["question"], "session_id": session, "visitor_id": "regression",
    }, timeout=60)
    answer = r.json()["answer"]
    errs = check(answer, t["check"])
    status = "PASS" if not errs else "FAIL: " + "; ".join(errs)
    failed += bool(errs)
    print(f"[{t['id']}] {status}")

print(f"\n{len(SET['tests']) - failed}/{len(SET['tests'])} PASS")
```

Замечания к прогону:

- тесты одной `session_group` выполняются с общим `session_id` (проверка диалога); остальные — с независимыми сессиями;
- тесты класса E проверяют консистентность: два одинаковых вопроса реестра должны давать одинаковый детерминированный ответ;
- набор не является полной проверкой: он покрывает ключевые классы поведения и служит быстрой регрессией после изменений промпта, retrieval или состава KB. После изменения KB или системного промпта ожидается повторный полный приёмочный прогон (приватный).
