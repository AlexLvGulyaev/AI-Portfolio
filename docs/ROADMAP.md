### C3. Вынос промпта `/case-match` из хардкода в управляемое хранилище

| | |
|---|---|
| Сейчас | Промпт подбора кейсов (Morphic-проба) — захардкоженная константа `_SYSTEM_RULES` в `backend/app/api/case_match.py`; правка = изменение кода + пересборка backend-контейнера ([`docs/PROMPT_ARCHITECTURE.md`](PROMPT_ARCHITECTURE.md) §7) |
| Цель | Промпт — вторая роль в управляемом хранилище `system_prompts` (рядом с промптом чата): правка и версии через Admin Console без пересборки, история изменений, активация |
| Почему не в релизе | Проба Morphic сознательно минимальна (без кеша/сессий/визарда); Case Pipeline (§5) уже планирует вторую роль в `system_prompts` — вынос промпта подбора решать в одном контуре с ней; известный дефект why-текста правится в первую очередь в самом промпте |

## 🔧 4. Инженерный долг (выявлено в ходе разработки)

| # | Задача | Суть | Влияние |
|---|--------|------|---------|
| 1 | **KB-sync: чистка чанков-сирот** | Sync переиндексирует только файлы выбранного состава; чанки документа, выпавшего из include-паттернов после одобрения, остаются в векторном индексе. Проявилось 03.09 (54 чанка источника Retail-Group после вывода документа из допуска; разово удалены штатной операцией). Фикс: post-sync-сверка «лишние store-документы → удалить/подсветить в `job.stats.verify`» | Корректность выдачи источников |
| 2 | **Мобильный оверфлоу 375px** | Горизонтальный оверфлоу на узких экранах (problem-grid ~245px на страницах кейсов, 68px на главной) | UX на мобильных |
| 3 | **Токенизация weaviate-классов** | text-свойства индекса создаются с дефолтной токенизацией `word` — фильтр удаления по `document_id` может захватить чужие документы (молчаливая потеря ~3% корпуса при реиндексации). Для прода (активен chroma) риска нет; **обязателен до переключения активного бэкенда на weaviate** | Блокер смены бэкенда |
| 4 | **Production-индексация weaviate** | Полный контур индексации weaviate — отдельная итерация (сейчас: паритет качества подтверждён, конвейер основной — chroma) | Устойчивость retrieval |
| 5 | **Кеш LLM-ответов** | LLM-ответы временно не кешируются (registry-only политика после устранения контаминации кеша). Вернуть с появлением структурного признака кешируемости | Latency и стоимость |
| 6 | **Fallback retrieval-канала** | Retrieval зависит от внешнего провайдера эмбеддингов; резервный канал поиска не реализован (решение владельца — пока не реализовывать; зарезервировано здесь как осознанное ограничение) | Устойчивость ассистента |
| 7 | **Полнота KB (класс C eval)** | ~9 стабильно падающих тестов класса C во всех прогонах: якорные тексты недостижимы или отсутствуют в корпусе — вопрос полноты KB, не retrieval. Итерация по содержанию источников | Корректность ответов |
| 8 | **«Грязные» формулировки (класс X)** | В трети размытых/эмоциональных формулировок ассистент отвечает уточнением-отказом вместо полезного ответа — зона роста в понимании фразы | Корректность ответов |
| 9 | **Минимальный запас p95** | p95 4956 мс при лимите 5000 мс; выбранное направление — стриминг SSE после UX-пачки (решение владельца 03.09); мониторинг latency — в силе | Latency |

## 🚀 5. Направления развития (утверждены владельцем)

### Case Pipeline (пост-релиз, концепция 02.09.2026)

Конвейер «GitHub-репозиторий кейса → KB → лендинг на канвасе»:

- лендинг как данные — JSON по фиксированной схеме `AIP Case Landing Page Standard v1.1` в БД; хардкод `src/cases/*.html` уходит, генератор остаётся сидом/фоллбэком;
- системный промпт сборки лендинга — вторая роль в управляемом хранилище `system_prompts` (вход — допущенные документы кейса, выход — JSON от hero до сценариев);
- контур доверия как в admission gate: immutable preview с commit SHA → утверждение владельцем → публикация;
- пилот — карточка telegram-ai-gateway (сейчас скрыта на витрине).

Открытые развилки (решаются отдельно): SVG как узлы/рёбра JSON, валидация выхода LLM, порядок относительно полного Morphic.

### Morphic — полный UX-контур

Проба реализована в релизе (подбор кейса по задаче: retrieval + реестр, why-объяснение по документам, откат флагом). Полный контур — сессии подбора, визард, сцена диалогового поиска как главный пресейл-механизм конверсии — проектируется отдельной задачей (UX-контракт → реализация → включение в presale-путь и E2E).

### Прочее

- **Кнопка «Скачать портфолио»** — сейчас заглушка на главной; решение о реализации (PDF-генерация / ссылка) — за владельцем.
- **Состав KB** — кандидаты: `BUSINESS_VALUE.md`, `SYSTEM_DEMO.md` (включение — с контролем пересечения фактов с уже индексированными документами).

## 📐 6. Принципы приоритизации

1. **Качество ассистента — прежде фич.** Пункты 7–8 раздела 4 влияют на метрику корректности ТЗ (≥90%) и берутся раньше новых функций.
2. **Утверждение владельцем.** Каждый пункт выходит в работу только по явной команде владельца; порядок разделов — не очередь исполнения.
3. **Соразмерность.** Инженерный долг фиксируется здесь вместо создания плановых документов на каждую единицу.
