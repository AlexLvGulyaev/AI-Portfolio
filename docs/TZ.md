## 1. Общая информация о проекте

### 1.1 Описание компании/контекста

AI Automation Portfolio — публичная платформа для представления портфеля реализованных AI-решений и инженерных компетенций специалиста по разработке и внедрению систем на основе искусственного интеллекта.

Портфель включает реализованные проекты в области LLM-приложений, AI-ассистентов, RAG, автоматизации бизнес-процессов, интеграций, обработки и анализа данных. Для проектов представлены описания решаемых задач, архитектура, технологический стек, инженерная документация, исходный код и работающие демонстрации — в зависимости от состава конкретного кейса.

AI Portfolio объединяет эти материалы в единый публичный продукт. ИИ-ассистент является одним из компонентов платформы и обеспечивает диалоговый доступ к базе знаний портфеля.

### 1.2 Проблема, которую решаем

Портфель включает 12 AI-активов. Подтверждающие их материалы распределены между сайтом, GitHub-репозиториями и работающими demo-сервисами. Потенциальному заказчику приходится самостоятельно искать и сопоставлять эти материалы, что усложняет поиск релевантного его задаче опыта и проверку фактической реализации. В результате большинство посетителей не доходит до целевого действия — обращения к исполнителю.

---

## 2. Цели и задачи

### 2.1 Главная цель проекта

Создать публичную AI-платформу, которая объединяет портфель реализованных решений и их доказательную базу и сокращает путь потенциального заказчика до нахождения релевантного кейса, подтверждения компетенций и обращения к исполнителю.

### 2.2 Измеримые показатели успеха (KPI)

| Метрика | Целевое значение |
|---------|------------------|
| Конверсия посетителей в обращения | Не установлено на этапе разработки: отсутствуют исторические данные. После запуска фиксируется baseline и устанавливается целевое значение для следующей итерации |
| Корректность ответов AI-ассистента | ≥ 90% на контрольном наборе вопросов |
| Время ответа AI-ассистента | < 5 секунд |

## 3. Пользователи и сценарии

### 3.1 Целевые пользователи

| Группа | Роль | Количество | Частота использования |
|--------|------|------------|----------------------|
| Потенциальный заказчик / ЛПР | Поиск и первичная оценка исполнителя для решения AI-задачи | Не определено до запуска | По мере возникновения потребности |
| Технический специалист заказчика | Техническая оценка компетенций, архитектуры и реализованных решений | Не определено до запуска | По мере необходимости |
| Партнёр / рекрутер | Оценка компетенций, опыта и реализованных проектов | Не определено до запуска | По мере необходимости |
| Администратор портфолио | Управление составом портфолио, проектами и связанными материалами | 1 | По мере актуализации |

### 3.2 Пользовательские сценарии (Use Cases)

**Сценарий 1: Поиск решения по бизнес-задаче**
- **Пользователь:** Потенциальный заказчик / ЛПР
- **Триггер:** «У нас много входящих заявок, нужно автоматизировать их квалификацию»
- **Ожидаемый результат:** AI-ассистент находит релевантные кейсы портфеля и предоставляет ссылки на их страницы.

**Сценарий 2: Проверка реализованного решения**
- **Пользователь:** Технический специалист заказчика
- **Триггер:** «Покажи архитектуру и исходный код решения для квалификации лидов»
- **Ожидаемый результат:** AI-ассистент предоставляет информацию о реализации и ссылки на доступные архитектурные материалы, GitHub и demo.

**Сценарий 3: Поиск проектов по технологии**
- **Пользователь:** Технический специалист заказчика
- **Триггер:** «Какие проекты реализованы с использованием RAG?»
- **Ожидаемый результат:** AI-ассистент находит соответствующие проекты и предоставляет ссылки.

**Сценарий 4: Оценка компетенций исполнителя**
- **Пользователь:** Партнёр / рекрутер
- **Триггер:** «Есть ли опыт разработки AI-ассистентов с PostgreSQL и FastAPI?»
- **Ожидаемый результат:** AI-ассистент находит проекты, подтверждающие соответствующий опыт, и предоставляет ссылки.

**Сценарий 5: Обращение по собственной задаче**
- **Пользователь:** Потенциальный заказчик / ЛПР
- **Триггер:** «Хочу обсудить похожее решение для нашей компании»
- **Ожидаемый результат:** Система предоставляет предусмотренный канал связи для обращения к исполнителю.

## 5. Данные и база знаний

### 5.1 Источники данных

| Источник | Формат | Объём | Статус |
|----------|--------|-------|--------|
| GitHub-репозитории 12 проектов портфеля | Markdown | 218 документов, ≈3,7 МБ | Существуют, требуют подключения к KB |
| Репозиторий AI Portfolio | Markdown | 13 документов, ≈0,25 МБ | Существует; требуется актуализация контента |
| Данные проектов AI Portfolio | PostgreSQL | 13 управляемых карточек (12 проектов + Prompt Review placeholder) | Актуализированы под новую главную страницу |
| Данные эксплуатации AI Portfolio | PostgreSQL | События и записи | Частично реализованы; требуется расширение |

### 5.2 Требования к данным

- **Конфиденциальность:** в публичную KB включаются только материалы, предназначенные для публикации. Секреты, API-ключи, персональные данные и внутренние материалы не включаются.
- **Актуальность:** состав KB соответствует актуальному составу опубликованного портфеля. Обновление выполняется через синхронизацию подключённых источников.
- **Доступ:** изменение состава источников KB и запуск синхронизации доступны только администратору AI Portfolio.

## 6. Технические требования

### 6.1 Платформа и интеграции

| Параметр | Значение |
|----------|----------|
| Подход | Code |
| Публичный интерфейс | Web (HTML5 / CSS3 / Vanilla JavaScript) |
| Admin Console | React + TypeScript + Vite |
| Backend | FastAPI + uvicorn |
| AI orchestration | Собственный ChatOrchestrator + PromptAssembly + provider layer |
| Database | PostgreSQL + SQLAlchemy + Alembic |
| Vector store / RAG | ChromaDB + OpenAI text-embedding-3-small |
| LLM-провайдер | OpenAI (primary) / GigaChat (fallback) |
| KB ingestion | GitHub API (httpx) + Markdown → plain text |
| Контейнеризация | Docker + Docker Compose v2 |
| Reverse proxy / static server | nginx |
| Edge TLS / reverse proxy | Traefik + Let's Encrypt |
| Runtime environment | VPS |
| Интеграции | GitHub |

Обоснование выбора: Code-подход выбран, поскольку AI Portfolio является production-сервисом с собственной бизнес-логикой, публичным интерфейсом, Admin Console и интеграциями. FastAPI используется для backend API, собственный orchestration layer управляет AI/RAG-пайплайном. PostgreSQL хранит структурированные данные, ChromaDB используется для векторного поиска по базе знаний, OpenAI — основной LLM-провайдер и провайдер embeddings, GigaChat — резервный LLM-провайдер. База знаний формируется из материалов проектов через GitHub API. Сервис развёрнут на VPS в Docker-контейнерах с публичным HTTPS-доступом через nginx и Traefik.

### 6.2 Нефункциональные требования

| Параметр | Требование |
|----------|------------|
| Время ответа AI-ассистента | < 5 секунд |
| Доступность | 24/7; недоступность AI-ассистента не блокирует публичное портфолио |
| Язык | Русский |
| Безопасность | HTTPS; аутентификация административного контура; секреты и API-ключи недоступны через публичный интерфейс |

## 9. Критерии приёмки

- [ ] Публичный AI Portfolio доступен по HTTPS 24/7.
- [ ] В портфеле представлены 13 управляемых карточек: 12 утверждённых проектов + Prompt Review placeholder.
- [ ] Для каждого завершённого проекта доступны предусмотренные публичные материалы и переходы к доказательствам реализации.
- [ ] Пользователь может пройти основной presale-путь: задача → релевантный кейс → доказательства → обращение.
- [ ] AI-ассистент отвечает на вопросы по материалам портфеля; корректность на контрольном наборе — ≥90%.
- [ ] Время ответа AI-ассистента — <5 секунд.
- [ ] Admin Console обеспечивает управление проектами, источниками знаний, синхронизацией KB и настройками AI.
- [ ] Недоступность AI-функций не блокирует просмотр публичного портфолио.
- [ ] Секреты, API-ключи и непубличные материалы недоступны через публичный интерфейс.
- [ ] Все контрольные E2E-сценарии успешно проходят после production deployment.
