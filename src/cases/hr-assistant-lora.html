LoRA достигает ~93% точности и сопоставимой с GPT-4o-mini latency

Проблема

HR-AI привязан к внешним API: стоимость, latency и политика

Крупные модели хорошо решают задачу, но заказчику нужна автономность, предсказуемая стоимость и прозрачные метрики, чтобы решить, доверять ли малой модели.

💰

Зависимость от внешнего API

Каждый вызов GPT-4o-mini — плата, квоты и политика провайдера; при масштабе это становится риском.

🔍

Нет специфичных метрик

Бизнесу нужны не общие LLM-оценки, а decision accuracy, FPR/FNR, MAE score и runtime smoke на HR-кейсах.

⚖️

Неочевидный trade-off

Малая модель может быть быстрее и дешевле, но пока неясно, сохранит ли она качество на реальных анкетах.

Решение

LoRA-адаптер + dataset engineering + многоуровневая валидация

Обучаем Qwen2.5-1.5B на размеченном teacher dataset, сравниваем с GPT-4o-mini на offline, external и Telegram smoke, и честно фиксируем failure modes.

📊

Teacher dataset HRA-EXP-V4

162 записи, 54 кандидата, 3 вакансии; obvious_match / borderline / obvious_no_match + hard negatives.

⚙️

LoRA fine-tuning

r=16, alpha=32, target_modules=all linear; best checkpoint — epoch 3, eval_loss 0.3273, peak VRAM 7.46 GB.

🧪

Runtime smoke

7/7 passed на hard-negative/edge кейсах; zero unexpected matches.

🆚

Сравнение с GPT-4o-mini

External validation n=102: LoRA 93.1% vs GPT-4o-mini 94.1%; vLLM latency p95 ~2.1 сек.

🔍

Честные failure modes

Telegram smoke 35% LoRA vs 43% GPT-4o-mini; teacher-label mismatch и hard-negative gaps задокументированы.
